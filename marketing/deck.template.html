Diagrams that can't go stale

ortho renders the five architecture views of the 4+1 model straight from SysML v2 text. No drawing tool, no cloud service, no model repository — a model file, one command, and an SVG you commit next to the code.

npx ortho render models -d part-definition -o diagrams/logical-view.svg

The problem

The drawing is the first thing to lie

  • An architecture diagram drawn by hand is a snapshot of an intention. Rename a component in the code and the picture keeps the old name — silently, indefinitely.
  • The picture lives in a binary file that only one person has the license to open, so it gets redrawn on demand rather than kept true.
  • Reviewers can't diff it. A pull request shows the model changed and the diagram changed, but not whether they agree.
  • So teams stop trusting diagrams, and the architecture goes back to living in people's heads.
Project · orthoWhy generate
The approach

One model. Five views. One command.

  • The text is the source of truth. Components, ports, requirements and scenarios are written in SysML v2 — the OMG standard notation, not an invented DSL.
  • Diagrams are build artifacts. Regenerate them like you compile code; never edit an SVG by hand.
  • CI keeps them honest. Re-render in the pipeline and fail on a dirty git diff — a stale diagram becomes a broken build.

Change a component

part controller : RadioController;

Every view that shows it updates

npm run diagrams git diff --exit-code diagrams/

The five SVGs on the following sheets were produced by exactly this command from the model files quoted beside them. Nothing was touched by hand.

  • No browser anywhere. SVG is written as text, so there is no headless Chrome to install, sandbox, or wait for.
  • No LLM at render time. The same model always produces the same bytes — diagrams diff cleanly.
  • Real text metrics. Font advance widths are embedded, so boxes fit their labels without measuring in a DOM.
  • Two dependencies do the heavy lifting: a parser generator and a layout engine. Both plain npm packages.

Process view

Launch, tap a person, fly itself

examples/auv-system/scenario-follow-person.sysml
action def FollowPerson {
    part pilot;
    part rcApp : Software::PilotApp;
    part targetTracking : Software::TargetTrackingEngine;
    part perception : Software::PerceptionPipeline;

    message launch from pilot to rcApp;
    then message takeOff from rcApp to flightControl;
    then message liveVideo of VideoStream
        from cameraCtrl to rcApp;
    then message tapPerson from pilot to rcApp;
    then message trackTarget of TargetBox
        from rcApp to targetTracking;
    then message obstacleMap of DepthGrid
        from perception to flightControl;
    then message avoidanceManeuver
        from flightControl to flightControl;
}

Development view

The model's own structure

Imports across the model files
// system.sysml - the architecture
package System {
    import Requirements::*;
}

// mechanics.sysml, electronics.sysml - the domains
package Mechanics {
    import System::*;
}

// software.sysml - architecture + deployment
package Software {
    import System::*;
    import Requirements::*;
}

Files are linked as one workspace, so a reference like System::Aircraft::fc resolves across them.

Self-contained

Runs anywhere Node runs

  • No external programs. No Enterprise Architect, no Graphviz binary, no headless browser. Node 18+ and nothing else.
  • No network at render time. Nothing is uploaded; models never leave the machine. Air-gapped builds work.
  • Deterministic output. The same model produces the same bytes, so an SVG diff means the architecture actually changed.
  • Installs as a dev dependency. It lives in node_modules and writes only where you point it — the tool's own sources never mix with yours.
  • 28 tests cover the grammar, every view extractor, layout and end-to-end rendering of the reference model.
  • Programmatic API too, if you would rather call the pipeline than the CLI.

Get started

Three lines to your first diagram

Install

npm install --save-dev ../path/to/ortho

Render

npx ortho render models \ -d part-definition \ -o diagrams/logical-view.svg

Keep honest

npm run diagrams && git diff --exit-code

Point it at a folder of .sysml files, choose a view, and commit the SVG. The picture is now part of the build.

Two complete worked models ship with the tool — an autonomous aerial vehicle and a coffee machine — each with requirements, use cases, a scenario, a design, and all five views generated from them.
